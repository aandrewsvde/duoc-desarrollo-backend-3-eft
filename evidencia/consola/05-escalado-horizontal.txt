6. El trabajo de Kafka tambien se reparte
==================================================================
Las replicas de ms-cuentas comparten grupo de consumidores, de modo que
Kafka les asigna particiones distintas del mismo topico. Es el otro lado
del escalado: no solo se reparten las peticiones HTTP, tambien los
eventos.

   
   GROUP           TOPIC                   PARTITION  CURRENT-OFFSET  LOG-END-OFFSET  LAG             CONSUMER-ID                                                HOST            CLIENT-ID
   ms-cuentas      banco.pagos.registrados 0          -               0               -               consumer-ms-cuentas-1-2da13aac-d3a9-4a55-a279-79a805dc685c /172.21.0.11    consumer-ms-cuentas-1
   Con un solo topico de una particion, solo una replica consume y las
   demas quedan en reserva: es el comportamiento correcto de Kafka, no
   un fallo. Para repartir de verdad hacen falta tantas particiones como
   consumidores, y eso se configura al crear el topico.
